# 偏移适配变更说明（WMPF 25707）

- 日期：2026-09-20
- 本机环境：微信 `Weixin.exe` 4.1.15.8，WMPF 运行时 **25707**
- `flue.dll`：`%APPDATA%\Tencent\xwechat\xplugin\Plugins\RadiumWMPF\25707\extracted\runtime\flue.dll`
- 运行环境：Node 20（目录由 `WMPF_NODE20_DIR` 指定，`01-安装依赖.bat` 会自动设置）+ frida 16.6.6

## 为什么之前不能用

三个独立问题叠在一起：

1. **版本探测失败**（最先撞上）
   `WMPFDebugger/src/index.ts` 的 `detect_wmpf_version_from_disk()` 只用
   `process.env.APPDATA` 一个来源。该变量在部分 shell / 服务环境里不存在 →
   直接返回 null；回退的「从进程路径取版本号」也失效，因为新版微信的
   `WeChatAppEx.exe` 跑在**不含版本号**的目录里
   （`...\Plugins\RadiumWMPF\WeChatAppEx.exe`）。
   最终报 `[frida] error in find wmpf version`。
   同样的 bug 也在 `scripts/project_doctor.py` 里，导致体检误报「未找到 flue.dll」。

2. **配置缺失** —— `frida/config/` 最新只到 `25297`，没有 25707。

3. **布局用错** —— 25707 属于 **modern** 布局，而内置的 `frida/hook.js`（124 行）
   与 `e0e1-wx/tools/hook.js` 都只认 legacy 的 `SceneOffsets`；
   而 `偏移提取工具/extract_wmpf_offsets.py` 也只产出 legacy 格式。
   modern 版本喂 legacy 配置 → hook 走 legacy 分支 → 崩。

## 以后微信再更新怎么办

1. 跑 `04-自动更新.bat`（微信不用关）——它会自动找最新运行时、判布局、写两处配置。
2. 跑 `03-检测依赖.bat` 确认体检全 OK。
3. 跑 `02-一键启动.bat` 启动。

若 sync 报「布局校验失败」，说明该版本结构又变了：
用 `-v` 看中间量，按 `偏移提取工具/reference.md` 的 modern 算法小节人工核对，
**不要手改 JSON 绕过断言**。

## 已知环境注意

- 必须用 **Node 20** 跑内置 WMPFDebugger（frida 16.6.6 需要 ABI 115）。
  若 `node_modules/frida/build/frida_binding.node` 缺失，说明装依赖时用错了 Node：
  ```bash
  cd WMPFDebugger/node_modules/frida
  "<node20>/node.exe" ../prebuild-install/bin.js
  ```
- 微信重启小程序时会**重建整棵 WeChatAppEx 进程树**，旧 hook 全部失效。
  `src/index.ts` 已有自动重注入循环，不要绕过它手动一次性注入。
